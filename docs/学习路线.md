# 学习路线：从插件到命令行工具链（commit-driven）

> 核心方法：**一步一 commit**。每步 = 一个可验证的里程碑，commit message 写清三要素：**改动 / 验证 / 收益**。完成时 `git log --oneline` 就是你的工具链学习目录。

## 目标

把 VS Code + AT32 插件的黑盒工作流，迁移为 **CMake + OpenOCD + GDB 命令行全家桶**：
看得见、可脚本化、可进 Git/CI、换调试器一行搞定、换芯片只改配置。

## 三层架构认知（地基）

| 层 | 管什么 | 本工程对应物 | 迁移状态 |
|---|---|---|---|
| 配置层（图形化） | 芯片怎么用：引脚/时钟/外设 | `*.ATWP`（AT32 Work Bench） | **保留，照常使用** |
| IDE/编辑器层 | 写代码界面 + 点按钮调工具链 | 插件（AT32 扩展）→ 逐步替换 | **被替换中** |
| 工具链层 | 代码→固件→跑起来 | CMake / Ninja / GCC / OpenOCD / GDB | **亲手掌握中** |

关键：配置层与工具链层**解耦**——ATWP 只生成代码，CMake 只管编译，互不干扰。换 IDE/工具链，ATWP 流程零改动。

## 路线（每步可独立验收、可回退）

| 步骤 | 内容 | 验证命令（预期） | 收益 | 状态 |
|---|---|---|---|---|
| 0 | 基线 + .gitignore | `git status` 干净，build/ 被忽略 | 每步 diff 可读、可回退 | ✅ |
| 1 | 命令行构建 | `cmake --preset Debug && cmake --build build/Debug`（[33/33] + 内存占用表） | 脱离插件编译，完整输出可见 | ✅ |
| 2 | 命令行烧录 | `tools\flash.ps1`（DPIDR 识别 + Verified OK + 复位） | 脱离插件烧录，换调试器=改 interface | ✅ |
| 3 | 命令行调试 GDB | `tools\debug.ps1`（server）→ `target remote :3333` → break/registers/bt | 条件断点/观察点/栈回溯/coredump | ✅ |
| 4 | 自建 launch.json/tasks.json | F5 走自己的配置 | 彻底摆脱插件，配置进 Git | ⬜ |
| 5 | 环境统一 | clangd 报错消失、单一构建目录/单一 GCC | 可复现环境 | ⬜ |
| 6 | coredump + CI | 崩溃 bt 定位；push 自动构建 | 崩溃可定位、自动化 | ⬜ |

docs/踩坑指南.md                  # 踩坑记录（强烈建议先读）
